# أثير القرآن — v7.1.2

الأربع محطات موجودة: القاهرة، السعودية، الكويت، الشارقة. يبدأ المشغّل بالمصدر المباشر لكل محطة. وسيط الصوت اختياري ويُستخدم فقط بعد فشل المصدر المباشر، وعند نشر الوسيط أو تهيئته.


## تحديث الشارقة 7.1.2 للمشروع المنشور بالفعل

ارفع محتويات هذه النسخة إلى **نفس مستودع GitHub المرتبط بـCloudflare** واضغط Commit changes. انتظر نجاح البناء الجديد في Cloudflare؛ لا تحتاج إنشاء Worker جديد أو تغيير إعدادات الربط. لو لم يبدأ البناء تلقائيًا، افتح إعدادات Builds وتحقق من ارتباط الفرع، أو استخدم Retry build بعد تأكدك أن البناء سيأخذ أحدث commit.

بعد النشر افتح `/api/status` على رابط Worker. النتيجة المطلوبة تحتوي `"version":"7.1.2"`. اختبر بعدها `/api/audio/sharjah` من Safari مباشرة، ثم من كارت الشارقة داخل الموقع. ملفات الواجهة تحمل v7.1.2 لتحديث الكاش.

التعديل يضيف relay/sharjah.mjs ويحدّث relay/audio.mjs. يرجى رفع الملفات داخل مجلد relay مع بقية المشروع. يعالج إطارات AAC المقطوعة بين الاتصالات، ويعيد المحاولة عند فشل تجديد المنبع بدل إنهاء بث المستمع من أول محاولة، ويرسل Content-Type القياسي audio/aac. هذا إصلاح لأوجه قصور مثبتة في الكود؛ لم يُثبت بعد أنه سبب كل انقطاع على جهاز المستخدم أو على خادم Cloudflare المنشور.

## ارفع الملفات على GitHub

1. فك الضغط وارفع **المحتويات** إلى جذر المستودع. لا ترفع ZIP نفسه ولا تضع المشروع داخل مجلد إضافي. index.html ومجلد assets يجب أن يكونا في الجذر.
2. استبدل النسخة القديمة بالكامل.
3. GitHub Pages: Settings → Pages → Deploy from a branch → main → /(root) → Save.
4. افتح رابط الموقع من Safari أو Chrome وابدأ الصوت بنقرة. ملفات الواجهة تحمل v7.1.2 لتحديث الكاش.

**GitHub Pages يشغّل المصادر المباشرة فقط.** ملفات الوسيط الموجودة في المستودع لا تعمل بمجرد رفعها عليه. لو القاهرة أو السعودية محجوبتان في متصفحك أو استمرت انقطاعات الشارقة، فعّل مسار Cloudflare أدناه. لا يلزم API Key للبث.

## مسار Cloudflare الاختياري — الواجهة والوسيط معًا

المشروع مهيّأ لـ Cloudflare Workers مع Static Assets، وليس Pages ثابتة فقط.

- اربط مستودع GitHub من Cloudflare → Workers & Pages → إنشاء Worker → استيراد مستودع Git.
- مجلد المشروع: جذر المستودع.
- أمر البناء: `npm run build` إن كانت الواجهة تطلبه. ملف Wrangler ينفّذ البناء أيضًا.
- أمر النشر: `npx wrangler@4 deploy`.
- لا تحتاج متغيرات أسرار أو قاعدة بيانات. Cloudflare يمنح الموقع رابط HTTPS بعد النشر.
- استخدم رابط Worker للاستماع. سيُفعّل الوسيط تلقائيًا مع بقاء المصدر المباشر هو المحاولة الأولى دائمًا.
- تابع حدود حسابك واستهلاكه من لوحة Cloudflare؛ لا تُفترض خدمة مجانية بلا حدود.

بديل من جهاز عليه Node.js 22 أو أحدث، داخل مجلد المشروع:

```bash
npm test
npm run deploy
```

سيطلب Wrangler تسجيل الدخول لحساب Cloudflare عند الحاجة. هذا الملف لم يُنشر على حسابك تلقائيًا.

### إبقاء الواجهة على GitHub Pages مع وسيط منفصل

بعد نشر Worker، عدّل assets/config.js ليكون:

```js
window.ATHIR_CONFIG = {
  relayBase: 'https://YOUR-WORKER.workers.dev/api/audio'
};
```

استبدل العنوان بعنوانك الحقيقي. استماع المتصفح يظل مباشرًا أولًا؛ عند فشله يستخدم الوسيط للمحطة نفسها فقط. لا يتحول إلى محطة مختلفة. لا يُفعّل مسار احتياطي غير منشور.

## المصادر

| المحطة | المصدر المباشر | المسار الاحتياطي |
|---|---|---|
| القاهرة | Radiojar MP3: 8s5u5tpdtwzuv | وسيط HTTPS للمصدر نفسه |
| السعودية | Radiojar MP3: 0tpy1h0kxtzuv | وسيط HTTPS للمصدر نفسه |
| الكويت | Mangomolo AAC عبر HLS | إعادة اتصال بالمصدر الصوتي نفسه |
| الشارقة | Kwikmotion icecast.audio بصوت AAC | وسيط يبقي الاستجابة مفتوحة ويجدد الاتصال الصوتي عند انتهائه |

أُزيلت مصادر HLS القديمة للسعودية والشارقة لأنها تضمنت H.264 فيديو. لا يوجد مصدر فيديو في القائمة الجديدة، ولا استخراج صوت داخل المتصفح من فيديو مخفي. مصدر القاهرة المستخدم في موقع misrquran.gov.eg فُحص أيضًا ولكنه تضمن فيديو، لذلك لم يُستخدم.

قد تعيد Radiojar التوجيه إلى HTTP. أُضيفت سياسة `upgrade-insecure-requests` لطلب ترقيته إلى HTTPS في المتصفحات الداعمة. لم يُثبت أن هذه السياسة تعمل على كل الأجهزة؛ الوسيط الاختياري يتبع التوجيهات بنفسه، يحتفظ بالتوكن المتجدد ويرفع الاتصال إلى HTTPS. لا نحفظ عنوان عقدة أو توكن مؤقت داخل الواجهة.

الشارقة أعطت استجابات صوتية قصيرة أثناء الفحص؛ المحاولة المباشرة تعيد الاتصال إذا انتهت بعد تشغيل فعلي، دون استنفاد المحاولات لمجرد انتهاء كل استجابة سليمة. قد تُسمع فجوة عند الاتصال المباشر. الوسيط يعيد فتح المنبع داخل استجابة صوت واحدة لتقليل اعتماد الاستمرار على JavaScript في الخلفية؛ هذا ليس ضمانًا لصوت بلا فجوات أو لتزامن كل مقطع مع ما يليه.

## إصلاحات المشغّل والخلفية

- حذف إيقاف pagehide وعدم مسح مصدر الصوت أو تدمير المشغّل بسبب إخفاء الصفحة.
- عنصر audio واحد، دون Web Audio ودون حيل الصوت الصامت.
- إلغاء مهلة التحميل عند إخفاء الصفحة ومنح فترة جديدة عند العودة؛ لا يُفسّر تعليق أحداث JavaScript أثناء القفل كتعطل فوري للبث.
- احترام الإيقاف اليدوي وأوامر النظام وعدم فرض إعادة التشغيل بعد إيقاف المستخدم.
- تفضيل HLS الأصلي على Safari في جميع المحاولات. hls.js بديل للأجهزة التي لا تدعم HLS أصليًا.
- Media Session: اسم المحطة والبلد وصورة وأوامر التشغيل/الإيقاف والتنقل، حسب دعم الجهاز.
- Audio Session playback عند توفر الواجهة.
- منع تشغيل مصدر HLS فيديو في مسار hls.js، وإعادة اتصال بتدرج زمني عند تعطل المصدر.
- لا توجد مهلة عمر إجمالية لاستجابة الوسيط. توجد مهلة لبدء الاتصال وأخرى عند انقطاع وصول البيانات. يُلغى اتصال المنبع عند إغلاق المستمع.

## حدود التشغيل في الخلفية

ابدأ الاستماع من **Safari على iPhone** أو **Chrome على Android**، ثم اقفل الشاشة. متصفح داخل واتساب أو أي تطبيق آخر قد يوقف الصوت عند ترك التطبيق. تحكم شاشة القفل يعتمد على دعم الجهاز والمتصفح؛ Media Session لا يمنح إذن تشغيل دائم.

لا يمكن للموقع ضمان استمرار الصوت عند إغلاق التبويب أو إغلاق المتصفح بالقوة، أو فقد الشبكة، أو تعليق الصفحة من النظام، أو مقاطعات المكالمات وتطبيقات الصوت الأخرى. إعادة الاتصال في JavaScript قد تتأخر حتى فتح الصفحة إن جمّدها النظام. تثبيت الموقع على الشاشة الرئيسية لا يضمن تشغيل الخلفية ولا يحوله إلى تطبيق أصلي.

على iPhone يُضبط مستوى الصوت من أزرار الجهاز؛ زر الكتم داخل الموقع يعمل بشكل مستقل.

## الملفات

- index.html وassets: الواجهة، صالحة لـ GitHub Pages.
- assets/config.js: تهيئة الوسيط الاختياري، معطل افتراضيًا على الاستضافة الثابتة.
- worker.mjs وwrangler.jsonc: نشر Cloudflare.
- relay/audio.mjs: الوسيط المحدود بمحطات معروفة؛ ليس وكيلًا مفتوحًا لعناوين المستخدمين.
- server.mjs: بديل Node وتشغيل محلي.
- scripts/build.mjs: نسخ ملفات الواجهة فقط إلى public للنشر؛ لا ينشر الشيفرة الخلفية كأصول عامة.
- test: اختبارات المشغّل والوسيط والمسارات.

hls.js 1.6.13 بترخيص Apache-2.0، والأعلام من flag-icons بترخيص MIT؛ التراخيص مرفقة. لا حسابات أو تحليلات زيارات في الواجهة. يتصل المستمع بخادم البث مباشرة أو عبر الوسيط الذي تنشره؛ المزودون يرون اتصالات الشبكة.
